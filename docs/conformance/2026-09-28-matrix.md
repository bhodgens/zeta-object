## [a] real bugs found and FIXED (4, each with RED/GREEN)

1. **Key/directory path collision** (`test_bucket_list_delimiter_basic`
   family; PUT `foo/bar` then PUT `foo/bar/xyzzy` → 500
   `mkdir ...: not a directory`). S3 keys are a flat namespace; mini-s3
   mapped them onto one directory tree.
   *Fix:* shadow data layout — a key whose flat path is provably unusable
   (ancestor file / target directory) stores data under
   `<bucket>/!data/<percent-encoded-key>`; readers resolve via the existing
   `StoragePath` metadata. `object_paths.go`, PUT/COPY/multipart writers.
   *RED/GREEN:* `TestPutObjectHandler_KeyBothDirAndFile`,
   `TestPutObjectHandler_FileThenDirKey`,
   `TestPutObjectHandler_ShadowLayoutNoFileAsDir` (RED: all 3 failed with
   500s pre-fix; GREEN post-fix, including under the concurrency stress
   suite — the shadow decision is pure, made inside the existing locks).
2. **Missing `?versions` sub-resource** — the suite's per-test teardown
   (`nuke_prefixed_buckets`) drives every cleanup through
   `list_object_versions` + `delete_objects`; without the sub-resource the
   teardown failed with `BucketNotEmpty` and errored **276 of 277** tests.
   *Fix:* `GET /bucket?versions` serving the unversioned wire shape (every
   object = one version, VersionId `null`, IsLatest true) — protocol
   plumbing only, NOT versioning support (version-specific reads stay 501).
   `bucket_versions.go` + dispatch in `main.go`.
   *RED/GREEN:* `TestListObjectVersionsHandler_BasicShape`,
   `_NoSuchBucket`, `_PrefixAndMaxKeys` (RED: 404/no-route before; GREEN
   after). Suite errors dropped 276 → 68.
3. **ListObjects V1 `marker` ignored** — `Marker=baz` was silently dropped
   (`parseListObjectsParams` only read V2 params), so marker-based
   pagination restarted from the top. *Fix:* parse `marker`, exclude keys
   `<= marker`, echo `Marker` and emit `NextMarker` (only when truncated
   AND a delimiter was requested — AWS V1 rule).
   *RED/GREEN:* suite `test_bucket_list_many`, `test_bucket_list_maxkeys_one`,
   `test_bucket_list_marker_*` RED before (duplicate pages) → GREEN after.
4. **Listing budget violated merged key order** — a delimiter roll-up
   consumed the page budget ahead of keys that sort BEFORE it, and the page
   dropped those keys; V1 `NextMarker` and V2 continuation tokens then
   re-served already-emitted groups. *Fix:* gather/emit merged-order items
   (keys + roll-ups interleaved in sorted order); budget consumed in that
   order; V1 `NextMarker` = last emitted item; V2 token = last emitted item
   so the next page consumes groups the previous page emitted
   (`groupConsumedByCursor`). *RED/GREEN:* suite
   `test_bucket_list_delimiter_prefix{,_underscore}` and
   `test_bucket_listv2_delimiter_prefix{,_underscore}` RED (wrong pages,
   repeated groups, wrong IsTruncated) → page1 `['asdf']`/next `asdf`,
   page2 `['boo/']`/next `boo/`, page3 `['cquux/']` not truncated — GREEN
   (V1 variants pass; the V2 variants remain FAIL only on the
   trailing-slash-key divergence below).

### Shared root cause of the 68 ERRORs

Every ERROR is a **teardown cascade**: a test that errors mid-multipart
leaves a `.metadata/.uploads/<id>.json` session behind; the next
`delete-bucket` returns `BucketNotEmpty: Bucket has in-progress multipart
uploads` (mini-s3's leaf-2.4 fix-10 invariant), which fails the suite's
`nuke_prefixed_buckets`, which fails the NEXT test's setup. The root
contributors are [c]-class tests (multipart copy, SSE-C part gets) that
abort mid-upload. Counting only non-cascade results: 77 FAILED are real
assertion results; the ERROR class is environmental.

## Known [a]-adjacent divergence (recorded, not fixed this leaf)

- **Keys ending in `/`** (`test_bucket_list_delimiter_prefix_ends_with_delimiter`,
  V1+V2): S3 allows a literal key `asdf/`; mini-s3's directory-mapped
  storage cannot represent a file whose name ends in the path separator
  (the `.meta` layout nests instead). Fixing requires the shadow-layout
  treatment for trailing-slash keys; recorded as follow-up work.
