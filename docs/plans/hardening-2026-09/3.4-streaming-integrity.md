# Leaf 3.4 — Streaming integrity: chunk-signature chain + trailers

## Goal
Verify chunk signatures for STREAMING-AWS4-HMAC-SHA256-PAYLOAD uploads instead
of accepting bodies blind. You own sigv4.go (decode path), types.go (no change
expected), and a new sigv4_chunked_test.go.

## Protocol being implemented

With x-amz-content-sha256: STREAMING-AWS4-HMAC-SHA256-PAYLOAD:
- Body = aws-chunked framing: `<hex-size>;chunk-signature=<64hex>\r\n<data>\r\n`
  repeated, final `0;chunk-signature=<64hex>\r\n<trailers>\r\n\r\n`.
- Seed = the signature of the HEADER request (the Authorization signature —
  passed into the decoder).
- Chunk string-to-sign per chunk:
  `AWS4-HMAC-SHA256-PAYLOAD\n<timestamp>\n<scope>\n<prev-sig>\n\n<hex(sha256(""))>\n<hex(sha256(chunk-data))>`
  where the empty-string hash line is the canonical "e3b0c442..." constant and
  prev-sig starts as the seed signature.
- chunkSig = hex(hmacSHA256(signingKey, chunkStringToSign)); chain: next prev
  = this chunkSig. Final chunk (size 0) same computation with empty data hash.
- Trailer variant STREAMING-UNSIGNED-PAYLOAD-TRAILER: framing parsed but
  chunk-signature fields are absent (or ignored) — keep current decode but
  with the truncation/corruption strictness from leaf 2.2. No signature math.

## Implementation

1. Extend decodeAWSChunked → new function in sigv4.go:
   `func decodeAndVerifyChunked(body []byte, seedSignature string, signingKey []byte,
   timestamp string, scope string) ([]byte, error)` — returns decoded payload,
   verifies every chunk signature (constant-time compare per chunk via
   hmac.Equal on hex strings), enforces final chunk present, size sums vs
   x-amz-decoded-content-length is checked at call sites (helper exists from
   leaf 2.2).
   Keep the old decodeAWSChunked for the UNSIGNED-TRAILER path (it already has
   leaf-2.2 strictness).
2. Wire-up problem: signature verification happens in authenticateRequest
   BEFORE handlers read the body; chunk verification needs the seed signature
   and signing key which exist only there. Do the full verification inside
   authenticateRequest when payload hash is STREAMING-AWS4-HMAC-SHA256-PAYLOAD:
   read the body, decode+verify, replace r.Body with a NopCloser over the
   decoded bytes, and set a request-scoped flag (context value or a header
   canonicalization is wrong — use context) so putObjectHandler/uploadPart
   skip their own decodeAWSChunked pass. Minimal handler-side change: in
   put/uploadPart, check `isDecodedStreaming(r.Context())` before decoding.
   These two one-line call-site edits in object_handlers.go /
   multipart_handlers.go are yours to make this wave (wave 5: those files have
   no concurrent owner — confirmed in master dispatch order).
3. Timestamp/scope for the chunk string-to-sign: reuse the request's x-amz-date
   ISO timestamp and the credential scope string already computed in
   authenticateRequest — thread them into the new function.
