## Features

1. ListMultipartUploads (GET /bucket?uploads): XML ListMultipartUploadsResult
   with Upload (Key, UploadId, Initiated), IsTruncated, MaxUploads (default
   1000), KeyMarker/NextKeyMarker. Scan .metadata/.uploads/*.json. Prefix param
   supported; key-marker/next semantics: lexicographic by Key then UploadId.
2. ListParts (GET /object?uploadId=...): XML ListPartsResult with Part
   (PartNumber, ETag quoted, Size, LastModified), PartNumberMarker (0 default),
   MaxParts (default 1000), NextPartNumberMarker, IsTruncated, PartNumberMarker
   honors "parts after this number". Validate uploadId + key match
   (NoSuchUpload otherwise) — reuse existing validation.
3. Expiry (was main.go:1270-1313 finding): uploads older than 7 days are
   auto-aborted lazily: every initiateMultipartUploadHandler (or a periodic
   goroutine — choose goroutine at 1h interval started from main(), owned by
   you via one wiring call; prefer the goroutine + document) scans .uploads,
   deletes sessions with Initiated older than 7d (meta file + _parts dir).
   Add `const multipartUploadExpiry = 7 * 24 * time.Hour`.
4. Minimum part size rule: S3 allows parts < 5MiB only for the LAST part.
   Enforce in completeMultipartUploadHandler: any non-final part with size <
   5MiB (5*1024*1024) → 400 EntityTooSmall. Constant
   `minPartSize = 5 * 1024 * 1024`.
5. ListParts/ListUploads responses use the xml.Header + xmlns pattern (call
   the writeXML helper in xml.go if it exists; otherwise marshal + xml.Header
   locally and note it for the orchestrator).

## Routing (main.go rootHandler, minimal)
- bucket-level GET with `uploads` query → listMultipartUploadsHandler.
- object-level GET with uploadId query → listPartsHandler.
