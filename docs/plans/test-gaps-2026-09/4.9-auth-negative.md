# Leaf 4.9 — Auth negative-fuzz corpus

## Goal
Mutational negative testing of authenticateRequest/authenticatePresigned:
every mutation of a valid signed request must REJECT with the right error
code — and nothing may panic or accept.

## Files you own
auth_negative_test.go (NEW). NO production edits. A mutation that is ACCEPTED
is a STOP-clause finding (report it; do not weaken the test).

## Build on
Reuse the signing helpers in main_test.go (buildSignedRequest) and
sigv4_presigned_test.go by REIMPLEMENTING minimal local versions if those are
not exported (they are package-main tests, so helpers ARE visible — just call
them; do not modify their files).

## Mutations (table-driven; each case = valid request + one delta)

Header-auth mutations:
1. Flip each byte position of the signature (loop over a 64-char sig — 64
   subtests) → every one 403 SignatureDoesNotMatch.
2. Signature truncated by 1 char, extended by 1 char, uppercased → 403.
3. x-amz-date ±1s (valid skew) → 200; ±16min → 403 RequestTimeTooSkewed.
4. Reorder SignedHeaders list in the Authorization header (sorted ↔ unsorted)
   → mismatch handling (pin actual: 403).
5. Add an extra signed header the request does not carry → 403
   (SignedHeaders mismatch rejection from leaf 2.2 fix 4).
6. Duplicate query param (prefix=a&prefix=b) with signature computed for one
   → 403 (canonical query includes both; client signed one).
7. Header name case games (X-AMZ-DATE vs x-amz-date) → still verifies (Go
   canonicalizes) — pin as 200.
8. Missing x-amz-content-sha256 with UNSIGNED-PAYLOAD absent → pin behavior.
9. Authorization header with spaces, tabs, CRLF injection attempt (\r\n in
   signature value) → reject, no panic, no log injection (G706 already
   handled; assert no panic).

Presigned mutations:
10. Valid presigned GET; tamper each of the 6 X-Amz-* params one at a time
    (value +1 char or swapped) → all 403/400 with the expected code per param
    (AuthorizationQueryParametersError for structural params,
    SignatureDoesNotMatch for signature-affecting ones).
11. X-Amz-Expires boundary: 0 → 400, 1 → OK, 604800 → OK, 604801 → 400,
    non-numeric → 400.
12. Presigned with BOTH Authorization header and X-Amz-Signature → header
    auth path wins (pin).
13. X-Amz-Credential with 4 or 6 scope parts → 400.
14. Replay: same presigned URL after expiry → 403 "expired".

Invariants across ALL cases: response is either an S3 XML error or success —
never a Go panic stack, never an empty 200.
