## Tests to write (inactivity_runtime_test.go or actions_test.go — your split)

triggerActions:
- Event with a matching pattern runs the action (swap runner, capture name+cmd,
  assert substituted+quoted values arrived).
- Pattern non-match runs nothing.
- `enabled: false` action never runs.
- Multiple matching actions run in config order.
- Missing .bucket-actions file → no panic, no run (covers loadActionsForPath nil path).

executeAction:
- `async: true` (default) returns without waiting: swap in a runner that blocks
  on a channel; assert executeAction returns before the runner unblocks; then
  release. Also assert the goroutine eventually ran (receive from channel with
  timeout).
- `async: false` blocks until the runner completes (runner that increments a
  counter; assert counter==1 when executeAction returns).

recordActivity / inactivity timer (use 50-100ms durations):
- Config with `after: 100ms, on: [put]`: PUT object via putObjectHandler (or
  recordActivity directly) → within 300ms executeInactivityAction fired (runner
  captured the inactivity command).
- Fresh activity inside the window re-arms: record at t=0, record again at 60ms
  (window 100ms) → no fire at 130ms, fires ~160ms. This is the timer.Stop-drain
  behavior from leaf 2.5 fix 8 — pin it.
- Activity type not in `on:` list does not reset or fire.
- executeInactivityAction runs the configured inactivity command (runner
  captures; assert no double-fire while already executing — second fire while
  first is in-flight is skipped or serialized per current code; pin actual
  behavior with a comment).

initializeInactivityTimers:
- Temp dataDir with a bucket containing a valid `.bucket-actions` with
  inactivity_timeout → tracker has an entry (expose via a small test-only
  helper or assert via recordActivity firing).
- Malformed file → no entry, no panic.
