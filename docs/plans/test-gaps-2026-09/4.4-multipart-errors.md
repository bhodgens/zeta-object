## Tests (add to multipart_handlers_test.go)

initiate:
- Invalid object key (.. traversal) → 400, no .uploads dir created.
- Nonexistent bucket → 404 NoSuchBucket.
- x-amz-meta-* captured into session CustomMetadata (assert via meta JSON).

uploadPart:
- partNumber=0 and 10001 → 400 InvalidArgument.
- partNumber non-numeric → 400.
- Bad uploadId format → 400 (validateUploadID).
- Valid id, missing session meta → 404 NoSuchUpload.
- Key mismatch → 404.
- aws-chunked body with lying x-amz-decoded-content-length → 400
  (the VerifyDecodedLength wiring from wave 2b — likely already covered;
  confirm, add if missing).
- Read-only .uploads dir → 500, part file not half-written (atomic write
  means no temp litter — assert dir has no *.tmp-* after).

complete:
- Part file deleted after uploadPart but before complete → 500 InternalError,
  PREVIOUS object version intact (the atomic-assembly contract — this is the
  key uncovered branch in assembleCompletedObject/copyPartsToAssembly).
- Empty Parts list → 400 InvalidPart.
- Unknown part number in request → 400 InvalidPart.
- ETag mismatch for one part → 400.
- Parts out of order → 400 InvalidPartOrder.
- Metadata-write failure after assembly (make the meta dir a FILE to force
  MkdirAll failure) → 500 AND final object NOT visible (temp not renamed) —
  pins the finalizeComplete failure ordering.
- NoSuchUpload for bad/foreign uploadId.

abort:
- Abort valid session → 204, meta + parts dir gone.
- Abort already-aborted → 404.
- Abort with key mismatch → 404 (leaf 2.3 fix).
- Abort with invalid id → 400.

Concurrent (pair with -race):
- Two concurrent uploadParts, same session, different part numbers → both
  succeed, meta has both parts (lock path).
