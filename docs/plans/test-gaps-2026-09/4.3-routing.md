# Leaf 4.3 — Dispatch routing matrix

## Goal
rootHandler's dispatch layer routes every production request, yet unit tests
bypass it: serviceLevelDispatch 0%, bucketLevelDispatch 33%,
objectLevelDispatch 36%. This is the layer that silently 405'd POST /?delete
before leaf 3.5.

## Files you own
routing_test.go (NEW). NO production edits — if the matrix exposes a routing
bug, STOP and report it (that is a finding, not a test failure to paper over).

## Approach
Requests through rootHandler (with the auth bypass your siblings already use —
check how existing handler tests authenticate; mirror that, do not invent a
new bypass). Assert on status code + a distinguishing marker per route (e.g.
XML root element or error code) — enough to prove WHICH handler answered.

## Matrix (table-driven, t.Run per cell)

Service level (empty bucket):
- GET / → 200 ListAllMyBucketsResult
- PUT/POST/DELETE/HEAD / → 405

Bucket level (`/{bucket}`):
- PUT → create (200/409 per state)
- GET (no params) → 200 ListBucketResult
- GET ?list-type=2 → 200 ListBucketResult
- GET ?location → 200 LocationConstraint
- DELETE → 204/409
- HEAD → 200/404
- POST → 405
- GET ?uploads → ListMultipartUploadsResult (leaf 3.3 route)
- POST ?delete → DeleteResult (leaf 3.5 route)
- GET ?acl → 501 NotImplemented (handleACL stub — also covers handleACL 0%)

Object level (`/{bucket}/{key}`):
- PUT (plain) → object stored
- PUT with ?partNumber&uploadId → UploadPart result
- PUT with x-amz-copy-source → CopyObjectResult (leaf 3.5 route)
- GET → 200 object; GET ?uploadId → ListPartsResult
- DELETE → 204; DELETE ?uploadId → 204
- HEAD → 200/404
- POST ?uploads → InitiateMultipartUploadResult
- POST ?uploadId → CompleteMultipartUpload (MalformedXML/400 is fine as the
  marker — proves routing)
- PATCH / OPTIONS → 405

Presigned + auth interplay:
- Request with X-Amz-Signature and NO Authorization → presigned path (assert
  via a valid presigned GET returning 200 — reuse the sigv4_presigned_test.go
  helpers if exported, else re-sign minimally)
- Authorization header present → header auth wins (bogus signature → 403,
  NOT AuthorizationQueryParametersError — proves the header path answered)
